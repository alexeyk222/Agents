## 2026-01-08: редизайн системы навигации

### Крупные изменения

1. **README.md переименован в navigation.md**
   - Более описательное имя файла
   - Лучшая обнаруживаемость
   - Самоописывающее назначение

2. **Добавлен паттерн организации по задачам**
   - Паттерн A: по функциям (специфично для репозитория)
   - Паттерн B: по задачам (несколько технологий)
   - Поддержан гибридный подход

3. **Токен-эффективная навигация**
   - Цель: 200–300 токенов на файл навигации
   - ASCII-деревья для структуры
   - Таблицы для быстрых маршрутов
   - Краткие описания (3-5 слов)

4. **Специализированные файлы навигации**
   - Сквозные задачи (например, `ui-navigation.md`)
   - Маршруты, сфокусированные на задачах
   - Ориентация на workflow

5. **Самоописывающие имена файлов**
   - `code.md` → `code-quality.md`
   - `tests.md` → `test-coverage.md`
   - `review.md` → `code-review.md`

### Новая документация

**Создано**:
- `guides/navigation-design.md` - как создавать файлы навигации
- `guides/organizing-context.md` - как выбрать организационный паттерн
- `examples/navigation-examples.md` - практические примеры

**Обновлено**:
- `context-system.md` - добавлены паттерн по задачам и принципы навигации
- `standards/templates.md` - добавлены шаблоны навигации

### Организационные решения

1. **Базовые стандарты (универсальные)**
   - Расположение: `core/standards/`
   - Область: все проекты, все языки
   - Пользователи могут редактировать, чтобы влиять на глобальный поток контекста

2. **Принципы разработки (доменные)**
   - Расположение: `development/principles/`
   - Область: программная инженерия
   - Существуют и базовые стандарты, и принципы разработки

3. **Контекст данных**
   - Расположение: `development/data/` (не верхний уровень)
   - Обоснование: слой данных — часть workflow разработки

4. **Специализированная навигация**
   - Включает быстрые маршруты + типовые паттерны
   - Пример: `fullstack-navigation.md` показывает стеки MERN, T3

### Путь миграции

**Фаза 0**: ✅ обновить документацию системы контекста (готово)

**Фаза 2**: реструктурировать категорию `development/`
**Фаза 3**: организовать `New-context-to-sort/`
**Фаза 4**: обновить все ссылки
