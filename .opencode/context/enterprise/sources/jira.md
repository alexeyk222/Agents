# Jira: постановка задачи и история решений

**Назначение**: извлекать из Jira scope задачи, критерии приёмки и историю
изменений логики данных, чтобы агент работал по реальной постановке.

---

## Что искать в Jira

- Текущая задача: описание, критерии приёмки, вложения, связанные задачи.
- Эпик и соседние задачи: что уже сделано, что в работе.
- История: инциденты и баги по тем же таблицам/атрибутам, изменения расчёта.
- Ссылки на Confluence внутри задач — лучший вход в документацию.

---

## Протокол поиска

1. **Если пользователь дал ключ задачи** (`DATA-1234`) — начни с неё:
   описание, критерии приёмки, комментарии, связи (`is blocked by`, `relates to`).
2. **Расширь контекст через JQL** — не больше 2–3 запросов:
   ```text
   project = DATA AND text ~ "transaction_date" ORDER BY updated DESC
   project = DATA AND issuetype = Bug AND text ~ "dm_transactions" AND updated >= -180d
   "Epic Link" = DATA-1000
   ```
3. **Выпиши ссылки на Confluence** из задач и передай их в поиск по Confluence.
4. **Сожми результат** до scope, критериев приёмки и известных проблем.

---

## Формат результата

```markdown
**Задача**: [DATA-1234](URL) · In Progress · исполнитель: команда DWH
**Scope**: мэппинг транзакционных атрибутов витрины на бизнес-глоссарий
**Критерии приёмки**: 1) все атрибуты описаны; 2) указана заполненность; 3) дашборд
**Связанное**: DATA-1180 (баг: дубли по `operation_id`), страница «Паспорт витрины»
```

---

## Ограничения

- ❌ Не создавай задачи, не меняй статусы и не пиши комментарии без явного
  запроса пользователя.
- ❌ Не переноси в ответ персональные данные клиентов из описаний и вложений.
- ✅ Закрытые задачи — это история, а не текущие требования: помечай статус.
